# MT5 License System

给编译后的二进制程序做**月度授权分发**的完整方案：打包侧 + 服务端 + 客户端三端，一套 Ed25519 + HKDF + AES-GCM 的密钥体系。

原始需求是给 MetaTrader 5 的 EA（`.ex5` 编译产物）做授权保护，但设计本身与 MT5 无关 —— 任何「编译后无法再改代码、又要控制谁能跑、还要能按月续费」的二进制分发场景都能直接套用。

```bash
python selftest.py        # 13 项加密层自测，纯本地，不需要服务端
```

```

通过 13 / 共 13
加密层行为符合预期。
```

## 一、要解决的问题

编译后的 `.ex5` 一旦发出去就无法再打补丁。传统的「发一个 exe 收一份钱」有三个绕不过去的点：

1. **文件被转手**：买家拿到 exe，直接发给别人就能跑
2. **到期无法回收**：按年卖，第二年到不了账，对方照样用
3. **密钥怎么轮换**：想定期换密钥，就得每期重新给所有用户发一遍新包

这套方案的设计目标就是同时解决这三点，且**不需要每个月改配置、不需要给用户重发包**。

---

## 二、核心机制：密钥每月自动变，但服务端不存密钥

```
MASTER（32 字节，只有你手里有）
   │
   └─ HKDF-SHA256(info="mt5-ea-payload|<月份>") ──→ K_2026-10
                                                  ──→ K_2026-11
                                                  ──→ K_2026-12
```

月度密钥**纯派生**，不落盘、不保存。月份到了，密钥自然就变了。服务端每次收到请求现算一次就行。

换 MASTER 的代价要提前知道：**所有历史月份的密文全部作废**。这是不可逆的，代码里用注释写死了这条。

### 三端各放什么

| 位置 | 允许持有的东西 | 泄露后果 |
|---|---|---|
| **打包侧**（你的机器） | MASTER + Ed25519 私钥 | 全盘皆输 |
| **服务端** | MASTER + Ed25519 私钥 | 全盘皆输 |
| **客户端**（用户机器） | Ed25519 **公钥** + payload 的 SHA-256 | **无害** |

客户端里只有公钥和哈希。公钥只能验签、算不出私钥；SHA-256 不是秘密。所以即使用户把 `launcher.exe` 完全逆向，也签不出新的授权响应。

这是整套设计里唯一不能让步的一条 —— 客户端**任何**能够自行派生密钥的实现，等价于把 MASTER 直接发给用户。

## 三、AAD 绑月：防止跨月重放

AES-GCM 的 AAD 里绑死月份：

```python
seal(plain, key, month)   # AAD = month
```

后果是：拿 10 月的密文配 11 月的密钥解，或者把 10 月的包塞进 11 月的响应里，都会在认证阶段直接失败。

自测里专门验了这条：

```
✓ 拿 11 月密钥解 10 月包 → 失败（月更生效）   → 已拒绝（InvalidTag）
✓ 包内月份与服务器宣称月份不一致 → 失败（AAD 绑定）   → 已拒绝（ValueError）
```

不绑 AAD 的话，攻击者只要攒住任意一个月的合法响应，就能在以后任意月份重放。这个漏洞很隐蔽 —— 加解密都对，只是保护的时间边界失效了。

---

## 四、自测覆盖的是「该拒绝的必须拒绝」

加密代码最危险的失败不是「解不开」，是「本该拒绝的却通过了」。所以 `selftest.py` 的重心全在负向用例上：

| 用例 | 期望 |
|---|---|
| 密文被改 1 bit | 拒绝（GCM 认证） |
| 用 11 月密钥解 10 月包 | 拒绝 |
| 包内月份与响应月份不符 | 拒绝（AAD） |
| 密文被截断 | 拒绝 |
| 包头被替换 | 拒绝 |
| 篡改授权响应体（换掉 key） | 拒绝 |
| 服务器自称有效但无签名 | 拒绝 |
| 换一对密钥自签 | 拒绝（客户端只认内置公钥） |
| 同一月份派生两次 | 结果必须一致 |
| 跨月份派生 | 结果必须不同 |
| 换 MASTER | 旧密文全部失效 |

外加端到端测试（`_test/`）：正常签发→启动链路、服务端拒绝链路、退出擦除链路。

## 五、三端组成

### 打包侧 `pack_tool.py`（460 行）

| 子命令 | 作用 |
|---|---|
| `init` | 生成 MASTER + Ed25519 密钥对，初始化授权库 |
| `publish` | 登记/更新一个 payload（可重复调用，累积成库） |
| `issue` | 签发授权（卡密） |
| `revoke` | 吊销授权，下一次联网立即失效 |
| `ea-disable` / `ea-enable` | 全局停用/恢复某个 payload |
| `license-ea-off` / `license-ea-on` | 针对单个授权停用/恢复 |
| `client-const` | 生成客户端内置常量（公钥 + 哈希） |

### 服务端 `server/server.py`（595 行）

标准库 `http.server` + `sqlite3`，零框架依赖。

| 路由 | 作用 |
|---|---|
| `POST /license` | 校验设备指纹 + 卡密 → 返回签名授权响应 |
| `GET /health` | 健康检查 |
| `GET /admin` | 后台（账号密码启动时随机生成，打印到控制台） |
| `/admin/lic`、`/admin/toggle` | 授权管理、开关 |

### 客户端 `client/launcher.py`（约 700 行）

打包成单个 `launcher.exe` 分发，职责：

- **设备指纹**：主板 UUID + CPU ID + 主机名取 SHA-256，换机器就失效
- **签名验签**：只认内置公钥，服务端被冒充也过不了
- **离线宽限**：`grace_hours: 72`，断网三天内仍可用，避免网络抖动导致误伤
- **本地缓存**：DPAPI 加密（Windows 用户态密钥），不落明文
- **退出擦除**：`wipe_passes: 3`，进程退出时把释放到磁盘的明文覆写清除
- **看门狗**：`watchdog_seconds: 3` 轮询，主程序被单独留下也带不起来
- **续期**：`--redeem` 输入卡密，不需要重新发包

## 六、跑通

```bash
pip install cryptography

# 1. 初始化（生成 keys/ 与授权库）
python pack_tool.py init

# 2. 登记 payload
python pack_tool.py publish --file your_ea.ex5

# 3. 起服务端
python server/server.py --host 127.0.0.1 --port 8787

# 4. 签发一个授权
python pack_tool.py issue --days 30

# 5. 自测
python selftest.py
```

## 七、关于本仓库的脱敏

这是一个**可运行的示例版**，不含任何真实密钥与真实产品：

| 已移除 | 原因 |
|---|---|
| `keys/`（MASTER、Ed25519 私钥） | 密钥永不进版本库 |
| 真实 payload（编译后的商业程序） | 属于客户产品，不是我的代码 |
| `server/payloads.json` 原始内容 | 含产品标识与真实指纹，已换成 `demo.ea.ex5` 示例 |
| 客户端内置公钥 | 换成占位值，实际使用时由 `pack_tool.py client-const` 重新生成 |
| `交付包/`（12MB launcher.exe） | 构建产物 |

`server/payloads/demo.ea.ex5` 是随机字节，只用于跑通自测。

---

## 八、设计红线（写在 `crypto_core.py` 文件头）

1. MASTER 与 Ed25519 私钥**只允许**出现在打包侧和服务端。客户端只放公钥 + SHA-256。
2. 月度密钥纯派生，服务端不落盘。换 MASTER = 历史密文全部作废。
3. AES-GCM 的 nonce 每次随机、同密钥下永不重复。重复即灾难性泄密。
4. 不要让客户端自己能派生密钥 —— 那等于把 MASTER 发给用户。
